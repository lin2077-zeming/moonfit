# moonfit 复测整改实施计划

## 目标

依据 `moonfit-AUDIT-RETEST-2026-11-25.md`，完成 R1–R9 的可验证修复，并统一 `fidelity` 的 profile、损耗状态、规格口径和项目边界。项目继续只提供 FIT 解码、分析和报告，不能把分析 profile 写成 TCX、GPX、KML 写出转换器。

## 工作单元

1. **先保留并核对已有实现**
   - 检查工作树、MoonBit 公开接口、生成的 `.mbti` 文件和现有门禁。
   - 保留既有门禁断言，不新增运行时依赖。

2. **代码与最小回归**
   - R1/R2：补齐 redact CLI 路径冲突和参数边界黑盒测试，确认错误时不产生输出。
   - R3/R4：保持 TCX 日期、结构和逐圈距离回退修复，补齐回归覆盖。
   - R5：保持严格 JSON 实数序列化，运行完整 JSON 语料门禁。
   - R6：将滑动平均和 TCX 点序列化都改为线性构建，保留数值结果回归。
   - R7：保持分段状态机不变量，补齐倒序、平台、跳变边界测试。
   - R8：确认 SWC 零值哨兵与有效非零 SWC 的处理语义，并明确报告范围。
   - R9：确认裁剪后压缩时间戳被重写为绝对时间，补齐跨低五位回绕覆盖。

3. **fidelity 模型与门禁**
   - 固定 `portable-core`、`standard-extended`、`loss-minimal` 三种 profile。
   - 输出 `analysis_only=true`、小数位、角度误差、赤道和活动纬度经度误差、状态、策略、规格和可逆性。
   - 门禁独立校验三种 profile、三种目标格式和坐标误差边界，禁止把 vendor observation 当作格式损耗。

4. **文档与申报材料同步**
   - 更新 README、边界、规范说明、测试说明和变更记录。
   - 明确 FIT semicircle 到十进制度是单位换算，损耗来自 profile 的序列化策略。
   - 用同一活动的多个合法输出策略解释兼容性、扩展保留和可逆性决策。
   - 检查仓库外的 `D:\MoonbitProject\November\提交版申报书.md`，只同步已经实现并可验证的范围。

5. **完整验证**
   - 运行格式、全目标检查、四目标测试、native release 构建。
   - 运行所有既有门禁及 self-test、fidelity、TCX、JSON、redact、文档、边界和语料完整性检查。
   - 复查 `git diff --check`、变更清单和申报口径后再提交。

## 完成判据

- R1–R9 均有实现和对应最小回归或黑盒证据。
- 复测文档要求的完整命令可复现，失败项已定位并修复或明确记录。
- 文档和申报书不宣称当前已有 TCX/GPX/KML 写出转换器。
- 所有状态、profile、误差和规格引用使用同一术语。
